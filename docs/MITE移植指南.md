# MITE → infx 移植工程指南（vanilla 1.6.4 源码版）

> 目标：把 MITE（MC 1.6.4 硬核改造）机制移植到 infx（NeoForge 26.1.2）时，不只是"类名/方法对上"，而是**七层全对齐 + 数值可玩 + 测试兜底**，确保移植后能在 26.1 正常游玩。
> 配套：《infx-MITE怪物机制移植差距分析.md》（机制状态总表）。源码四源见 §0.2。
> 更新：2026-08-16

---

## 0. 核心思想

### 0.1 三层目标（每个机制移植完都要同时满足）
| 层 | 问的问题 | 失败表现 |
|---|---|---|
| **机制正确** | 行为忠实吗？触发/持续/结束与 MITE 一致吗？ | 行为漂移、半实现 |
| **数值合理** | 玩家能玩吗？打得动、扛得住、有反制？ | 硬控、秒杀、打不动、数值崩坏 |
| **工程健壮** | 不崩、不卡、多人一致、存档兼容、关得掉？ | 崩溃、卡顿、单机/服务器不一致、存档损坏 |

**核心方法一句话：搬运增量，不做搬运基线**——MITE 只改了 1.6.4 的一小部分，把"改了什么"精准搬到 26.1.2，其余交给 vanilla 原生。

### 0.2 四源对照
| # | 源 | 路径 | 作用 |
|---|---|---|---|
| ① | vanilla 1.6.4 | `mc/1.6.4-src/src/minecraft/net/minecraft/src/` | 基线（`net.minecraft.src` 平铺，`Entity` 前缀） |
| ② | MITE | `mc/mite/src/net/minecraft/` | 增量本体（按功能分包 `entity/ world/ item/`） |
| ③ | vanilla 26.1.2.94 | `inf-x/build/moddev/artifacts/minecraft-patched-26.1.2.94-sources/net/minecraft/` | 目标（是否已原生） |
| ④ | infx 实现 | `inf-x/src/main/java/com/pixulse/infx/` | 落地 |

## 一、七层对齐框架

对每个机制，自上而下过七层。**每层都问"1.6.4/MITE 是什么形态 → 26.1 该怎么落地 → 怎么验证"**。映射（类名/方法）只是 L4/L5 的一部分，不是全部。

### L1 语义层（机制本体）—— 先写规格，再写代码
- **做法**：实现前先把机制写成一句话状态机：*触发条件 → 进行中行为 → 结束条件/副作用*。语义决定了实现方式。
- **精确规则**：语义是"从某时刻持续 N 秒"的，用**到期点**实现（记录/推导结束时刻），不要"每 tick 重置剩余时长"（血月雷暴被续期到 24h 的教训）。
- **验证**：GameTest 断言机制的**终态与边界**（结束时刻、最多触发一次等）。

### L2 数值层（参数体系）—— 三种来源，逐项判定
搬数值前先判定它属于哪种来源，**不要无脑照抄 MITE**：

| 来源 | 判定 | 处理 |
|---|---|---|
| **vanilla 同源** | ① 1.6.4 和 ③ 26.1.2 数值一致（僵尸 `movementSpeed=0.23/attack=3/HP=20` 已验证相同） | **直接可用，别动** |
| **MITE 增量** | ② MITE 对 ① 的改动（僵尸 attack 3→5） | **照搬增量** |
| **体系换算** | 数值所属体系跨版本语义变了 | **按换算表重定参** |

**已核实的精确换算表**（直接用）：

| 量 | 1.6.4/MITE 形态 | 26.1.2 形态 | 处理 |
|---|---|---|---|
| 移动速度（新 AI 怪） | `movementSpeed=0.23` | 速度系 0.23 | **直接抄**（同源） |
| 移动速度（old-AI 怪） | 0..1 节流值 | 速度系 | **×0.375**；不确定先查 MITE 该怪属于哪种 AI |
| 生命 / 攻击 | 裸值（僵尸 20 / 3） | 属性裸值 | 直接；只搬 MITE 增量 |
| 护甲 | **线性 `armor/25`** 减伤 | **非线性 `armor+toughness`，随伤害变化** | 不能照搬护甲值语义；按现代公式校准相对强度 |
| 难度乘数 | **整数档 0/1/2/3** | `getSpecialMultiplier()` **0.75/1.5/2.25 + 区域难度** | 依赖"难度乘数"的公式必须重定参 |
| 减速/增益效果 | 每级 15% | 同 | amplifier 5 = 90%（近似硬控），照抄前先推演 |
| tick 时长 | 20t/s | 20t/s | 时长直接换算；昼夜/月相走 `MoonPhase` 窗口 |
| 概率 / 倍率 | float | float | 直接搬，**clamp [0,1]** |

**相对强度三问**（数值定完必答）：① 几下打死玩家？② 玩家几下打死它？③ 反制资源（银/附魔/火）当时可得吗？三个答案都"合理"才算过。

### L3 行为层（AI / 状态机）
- goal 生命周期：`canUse / canContinueToUse / start / stop` 对称（开了不关 = 行为卡死）。
- **优先级冲突**：同优先级 `goalSelector.addGoal` **先注册者赢**（骨修复 goal 抢走弓的教训）。
- **更新频率**：1.6.4 `updateTask` 每 tick vs 现代 `requiresUpdateEveryTick()`；高频率逻辑要节流（每 tick 扫 3×5×3 找火把 = 性能坑）。
- 寻路 API：1.6.4 `getNavigator().tryMoveToXYZ` → 26.1 `PathNavigation.moveTo`；`createPath` 返回 null 的判定差异。
- **验证**：GameTest 走完"触发→进行→结束"全周期；高频率逻辑加计数器断言频率上限。

### L4 触发层（事件 / 钩子 / mixin）—— 只从唯一入口实现
- **触发链完整性**：`Mob.finalizeSpawn` 会**连带触发** `FinalizeSpawnEvent` —— 事件里做了的事，外面别再显式调（替换刷怪双装备教训）。
- **事件时机**：Pre/Post/cancelable、`setCanceled`/`setSpawnCancelled` 用对；`LivingIncomingDamageEvent` 的 Pre 修改金额 vs `Post` 结算。
- **dist 分离**：客户端（渲染/红眼/提示）只读客户端状态；服务端逻辑守 `ServerLevel`；网络握手客户端判定别碰服务端字段。
- **mixin 注入点**：注入位置（HEAD/TAIL/返回值）、歧义（多个同签名调用要 selector 指定）、`ModifyReturnValue` vs `Inject` 的语义。
- **禁止双入口**：同一机制一个事件或一个 mixin，不要两个各写一半。
- **验证**：破坏断言确认事件真的触发；同机制只 grep 到一个入口。

### L5 数据层（注册 / 资源 / 生成 / 配置）
- 注册表：实体 `DeferredRegister` + 属性 `createAttributes()` + 渲染器 + 语言 key **四项齐**（漏一个 = 隐形成隐形/无贴图/无翻译）。
- 数据驱动：loot table / `mob_spawn_rules` / tag / datagen Provider —— 由 Provider 生成，跑 `runData` 提交 `src/generated/`（不要手改生成结果）。
- 配置（Jupiter config）：**所有机制必须有关闭开关**，且开关要能真正关掉全部子效果（见 §四）。
- **验证**：`EntityRenderersTest` / datagen 回归；新实体 spawn 后查渲染/刷怪/掉落齐全。

### L6 持久化层（SavedData / 存档）
- 编解码**对称**（读多少写多少）、缺省字段、null 处理（旧档没有该 key）。
- 脏标记：改了数据要 `setDirty()`，否则重启丢失。
- 跨维度/跨版本：按 world/维度 key 隔离；缓存按玩家 UUID 要 TTL + 卸载清理（静态 Map 泄漏教训）。
- **验证**：单测编解码往返；手工存档读写一次确认不丢。

### L7 网络层（多人）
- 配置握手 / 自定义 payload：两端 handler 对称、**无 ack 超时**风险（旧客户端挂起）、协议版本。
- 集成服务器 vs 专用服务器**语义不同**：单机/LAN 下客户端与服务端共享配置文件，开关不对称是**有意场景**不是错误（dev 握手矛盾教训）；专用服务器两端独立。
- 世界级状态（天气/月相/SavedData）只服务端权威，客户端只读。
- **验证**：单机 + 局域网 + 专用服务器各跑一遍。

## 二、可玩性校验（确保移植后能正常玩）

移植完不是结束，**开一个新档从第一天玩到后期**，逐条过：

| # | 检查项 | 失败表现（必须避免） |
|---|---|---|
| 1 | **开局可达性**：机制是否有反制手段 | Shadow/Wight 仅银/魔法可伤 + 全群系刷 → 前期打不动；Stalker 5% 透明 + 熄灯 → 无法瞄准 |
| 2 | **数值闭环**：伤害/生命曲线 | 几下被秒 / 打几十下不死 / 硬控（90% 减速连击） |
| 3 | **难度曲线**：tension/天数增长合理 | 前期就遇到后期怪 / 后期怪还不如前期 |
| 4 | **资源经济**：掉落/配方可推进 | 需要银/附魔才能打，但银/附魔前没有来源 |
| 5 | **性能**：每 tick 计算、实体量 | 33³ 扫描、每 tick 45 格扫描、缓存不清理 |
| 6 | **存档兼容**：SavedData 迁移 | 旧档加载崩溃/丢数据 |
| 7 | **多人一致性**：单机 vs 服务器 | 单机有、服务器没有（或反之）的机制 |

**验收标准**：一个新档能无外挂从第 1 天玩到后期（跨月相、过血月/蓝月、下矿到 y<40、进下界/末地），全程无崩溃、无卡死、无不可反制遭遇、帧率不掉。**只有自动化测试通过但没跑过档，不算完成。**

## 三、测试策略（bug 防护）

### 3.1 测试金字塔
| 层 | 工具 | 覆盖 | 门槛 |
|---|---|---|---|
| 单测 | `src/test` JUnit | 纯函数/公式/概率/窗口边界/编解码 | 每个数值公式必测边界 |
| GameTest | `runGameTestServer` | 机制行为/AI 全周期/事件触发/生成 | 新增机制必有测试 |
| 集成 | `runGameTestServer` 全套 | 回归 | 失败集 ≤ master 既有失败子集 |
| 性能 | 大规模刷怪/长时运行 | 每 tick 成本、实体量 | 不卡、不 OOM |
| **手工档** | 真机跑 | 手感/体验/存档/多人 | **必做**（§二清单） |

### 3.2 边界值必测清单
- 概率：0、1、`clamp` 两端（首领概率、传火概率）。
- 时间窗：`13000/23000`（夜）、`6000`（雷暴起点）、`6000+13000`（雷暴终点）——**含/不含边界**。
- 数值：0（护甲 0、attack 0、modifier 0）、负（缓冲）、NaN/除零（y 极值、distance 0）。
- 持久化：SavedData null/旧档缺字段、跨维度缓存过期。
- 配置：关闭开关 → 全部子效果消失；`enabled=false` → 机制完全关停。

### 3.3 关键技法
- **破坏断言验证**：新 GameTest 先故意改错一条断言，确认它真的会失败（否则可能是静默通过）。
- **失败集对比**：跑 `runGameTestServer`，失败必须是 master 既有失败的真子集；新增失败 = 你的改动引入。
- **单机+服务器双跑**：网络/世界状态机制两边都验证。

## 四、落地准则（工程规则，历史教训抽象）

1. **先查 vanilla 已原生**（L2 判定第 1 步）：机制在 ③ 26.1.2 已实现 → 调参/继承，不重写。历史重灾：僵尸首领（`Zombie.handleAttributes` 原生掷，1.6.4 就有 `Leader zombie bonus`）、转化 Normal 50%（`killedEntity` 原生）、南瓜头（`finalizeSpawn` 原生）。差距文档 §三「原生基础」表先查再动手。
2. **禁双入口**（L4）：一个机制一个事件/mixin；`finalizeSpawn` 连带触发事件，勿再显式调。
3. **配置开关统一出口**：机制所有消费方走同一个集中谓词（如 `isBloodMoonFrenzied`），防"半开关"。
4. **时间机制用到期点**（L1）。
5. **跨提交交互交叉验证**：新机制与既有机制（权限、月相、上限）一起想。
6. **删使用点必删声明点**：重构连带清理死钩子，防 javadoc 与行为不符。
7. **数值照搬前换算+推演**（L2）：过换算表 + 相对强度三问。
8. **配置必有关闭开关**（L5）：且能真正全关。
9. **客户端/服务端 dist 语义**（L7）：集成 vs 专用服务器、配置共享 vs 独立。

## 五、常见坑速查表

| 坑 | 表现 | 规避 |
|---|---|---|
| vanilla 已原生还重写 | 叠乘/重复 | L2 判定 + 差距文档 §三 |
| 旧数值未换算 | 硬控/打不动/难度乘数错 | L2 换算表 + 相对强度三问 |
| `finalizeSpawn` 连带触发 | 逻辑跑两遍 | L4 唯一入口 |
| 配置门分散 | 关不掉子效果 | §四.3 集中谓词 |
| 时间机制重复重置 | 永不结束 | L1 到期点 |
| 同优先级 goal 覆盖 | 行为被抢 | L3 检查优先级与注册顺序 |
| 死代码保留 | javadoc≠行为 | §四.6 |
| 缓存不清理 | 内存增长 | L6 TTL+卸载清理 |
| 事件两侧不对称 | 挂起/崩溃 | L7 ack 超时 |
| 新 GameTest 静默通过 | 没测到 | §3.3 破坏断言 |
